# Lessons

- When a user asks for an admin chrome restyle, also audit related portalled controls like select/dropdown popups so the full interaction stays visually consistent.
- When capturing design-system references in planning docs, verify they match the app platform first; do not carry a web-only UI library into React Native phase context.
- **React Native Reanimated version drift**: Always pin `react-native-reanimated` to the exact version Expo SDK expects (run `npx expo install --check react-native-reanimated` to verify). Never rely on a `~` range that resolves to a newer JS package than the native binary — the mismatch throws a fatal ReanimatedError at startup. The CONTEXT.md pitfall note "use ~3.19.5" was wrong; Expo SDK 53 requires ~3.17.4.
- **react-native-iconify babel registry drift**: Every icon string used anywhere in code must be explicitly listed in `babel.config.js` under the `react-native-iconify/babel` plugin's `icons` array. If an icon is added to a component but not to babel.config.js, it compiles silently but renders blank/missing at runtime. After adding any new icon to a component, always add it to babel.config.js and restart Metro to rebuild. Planners must include babel.config.js icon additions as explicit tasks when new icons are introduced.
