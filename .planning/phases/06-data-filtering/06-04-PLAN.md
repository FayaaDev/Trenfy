  <files>tools/nocodb_trends_client.py, tests/test_phase06_api_filters.py</files>
  <behavior>
    Multi-platform (API-08):
    - platform="youtube,x" → NocoDB filter: (platform,anyof,youtube,x)
    - platform="youtube" (single, no comma) → NocoDB filter: (platform,eq,youtube) — unchanged
    - platform=None → no platform filter — unchanged

    Full-text search (API-09):
    - q="taylor" → NocoDB filter: (title,like,%taylor%)~or(description,like,%taylor%)
    - q="" or q="   " → no search filter applied
    - q=None → no search filter applied
    - q filter is joined to other where_parts with ~and wrapping

    Metric floor (API-12):
    - min_metric_value=1000 → NocoDB filter: (metric_value,gte,1000)
    - min_metric_value=None → no filter

    All filters combined (API-08 + API-09 + API-12):
    - platform="youtube,x", q="gaming", min_metric_value=500 → all three conditions joined with ~and

    Sort (covered in list_trends, NocoDB receives the mapped sort string)
  </behavior>

    1. Add `q: Optional[str] = None` and `min_metric_value: Optional[int] = None` to `query_trends()` signature.

    2. Replace the platform where_part:
       ```python

               where_parts.append(f"(platform,anyof,{platform})")

    3. Add after existing date filters:
       ```python
       if q and q.strip():
           q_clean = q.strip()
           where_parts.append(
               f"(title,like,%{q_clean}%)~or(description,like,%{q_clean}%)"

Check NocoDB docs pattern from `batch_check_duplicates` which already uses `anyof` — use the same approach. If NocoDB rejects the nested ~or, fall back to two separate like conditions joined with ~or directly in the where string without extra wrapping.
